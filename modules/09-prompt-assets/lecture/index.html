    M9 — Prompt 资产体系建设¶

    时长：1.5 小时 | 受众：全员必修 | 前置要求：M1–M5（建议全部完成）

    学习目标¶

    完成本模块后，你能够： 1. 理解为什么团队级 Prompt 资产比个人 Prompt 更有价值 2. 按场景分类整理团队已验证的 Prompt 模板 3. 为 Prompt 模板建立质量评估标准 4. 设计一套团队 Prompt 库的维护流程（GitHub Issues + PR） 5. 贡献至少 1 条经过验证的 Prompt 到团队资产包

    第一节：为什么需要 Prompt 资产化？（15 min）¶

    没有资产化的团队现状¶

    每个人独立摸索 Prompt
↓
同样的场景，不同人的输出质量差异很大
↓
好的 Prompt 存在个人电脑，离职后丢失
↓
新成员每次都从零开始

    有 Prompt 资产库后¶

    好 Prompt 经过验证后收录到共享库
↓
团队成员直接复用，质量有保证
↓
持续迭代优化（PR 流程）
↓
新成员可以快速达到团队平均水平

    Prompt 资产的价值¶

    维度 个人 Prompt 团队 Prompt 库
    质量 参差不齐 经过验证和 Review
    传承 依赖个人记忆 文档化，永久保存
    迭代 个人随意修改 版本控制，可追溯
    新人上手 需要自行摸索 直接使用成熟模板

    第二节：Prompt 模板标准格式（20 min）¶

    每条团队 Prompt 模板应包含以下元数据：

    ## [模板编号] [模板名称]

**场景**：一句话描述适用场景
**推荐工具**：Kimi / DeepSeek / 通义千问 / GitHub Copilot
**效果评级**：⭐⭐⭐⭐（1–5星，团队使用反馈）
**贡献者**：[姓名/工号]
**最后验证日期**：YYYY-MM-DD
**已知局限**：（如有）

---

### Prompt 正文
    [完整 Prompt 内容，占位符用 [大括号] 标注] 
    ---

### 使用说明

1. 将 [占位符] 替换为你的具体内容
2. [可选步骤或注意事项]

### 典型输出示例

[粘贴一个好的输出示例，让用户知道期望结果]

### 已知效果不佳的场景

[记录哪些情况下这个 Prompt 表现不好]

    第三节：Prompt 质量评估维度（15 min）¶

    在贡献一个 Prompt 前，用以下标准自评：

    评估项 标准 得分（1–5）
    可用性 新人按说明使用后，是否能得到预期输出？
    稳健性 对不同场景的输入，输出质量是否稳定？
    节省时间 相比不用 Prompt，节省了多少时间？（估算分钟）
    格式规范 包含所有必要的元数据和说明？
    示例质量 示例输出是否清晰展示了期望结果？

    入库门槛：可用性 ≥ 4 分，且在至少 2 个不同场景下验证过。

    第四节：GitHub 维护流程设计（20 min）¶

    贡献新 Prompt 的流程¶

    1. 在 prompt-templates/ 找到对应分类文件
2. 按标准格式添加新模板（用 Issues 或直接 PR）
3. 添加 [需要验证] 标签
4. 团队其他成员使用并反馈（Issue 评论）
5. 经过 2+ 人验证后，去掉 [需要验证] 标签
6. 定期（每月）Review 效果评级，更新失效的 Prompt

    Issues 标签规范¶

    [prompt-new]       新 Prompt 提案
[prompt-update]    现有 Prompt 改进建议
[prompt-invalid]   某个 Prompt 在特定场景失效
[prompt-need-test] 需要更多成员验证

    月度 Prompt 复盘议程（建议 30 分钟/月）¶

    1. 本月使用最多的 3 个 Prompt（数据来自 Issues 评论）
    2. 发现失效的 Prompt（场景变化/模型更新导致）
    3. 讨论 1–2 个新场景是否需要新 Prompt
    4. 更新效果评级

    第五节：今天就贡献一条（15 min）¶

    任务¶

    在完成 M1–M8 的学习后，你应该已经积累了几个有效的 Prompt。 今天就将最有价值的一个整理成标准格式，贡献到团队库。

    检查清单¶

    • [ ] 选择了一个在工作中确实有效的 Prompt
    • [ ] 按标准格式整理了模板元数据
    • [ ] 写清楚了使用说明（哪些 [占位符] 需要替换）
    • [ ] 提供了一个真实的典型输出示例
    • [ ] 标注了已知的局限性（诚实很重要！）
    • [ ] 在 GitHub 对应的分类文件中提交了 PR 或 Issue

    第六节：Skill 机制与 grill-me 实战（20 min）¶

    配套概念：M2 已讲 MCP / CLI，本节讲"Skill"——AI 客户端里另一种可复用能力封装。

    什么是 Skill¶

    Skill（技能） 是 AI 客户端（如 Claude Code、CodeBuddy）的可复用指令包：把一套专家工作流（角色设定 + 步骤 + 模板）预先写好，需要时一句话触发，而不用每次重新拼 Prompt。

    • 分发方式：社区平台如 skills.sh 提供大量现成 Skill；
    • 本质：一段结构化的"专家 SOP"，被加载后 AI 会按它执行；
    • 与 Prompt 模板的区别：Skill 更重"流程"，可跨会话持久存在，并常带触发词。

    安装与使用思路（以 mattpocock/skills/grill-me 为例）¶

    grill-me 是一个"拷问式"Skill：当你提出一个设计/方案，它反过来深挖漏洞、逼你补全思考盲点——非常适合测试方案评审。

    伪步骤（不依赖具体内部环境）：

    1. 获取 Skill：从 skills.sh 找到 mattpocock/skills/grill-me
2. 放入客户端 Skill 目录（按客户端约定，如 ~/.codebuddy/skills/ 或等价路径）
3. 触发：在对话中调用该 Skill（通常输入其名称/触发词，如 "grill me on ..."）
4. 输入：把你的测试方案 / 架构设计 / 用例设计贴给它
5. 输出：AI 以"审阅者"身份提出尖锐问题、风险点、遗漏假设

    实战：用 grill-me 评审一份测试方案¶

    你：grill me on 这份"新员工入职"功能的测试方案：
[粘贴你的测试维度 + 用例清单 + 覆盖策略]

grill-me 可能的追问方向：
- "你假设兼职和全职走同一套校验，依据是什么？"
- "30 个字段里，哪些字段的边界值你没覆盖？"
- "如果创建中途超时，数据处于什么状态？你的方案没提。"
- "权限场景你只测了 Manager，HR 角色呢？"

    注意事项¶

    • Skill 是"专家视角"，输出是挑战而非结论，最终决策仍靠人；
    • 团队可把内部评审 SOP 也沉淀成自有 Skill，复用 grill-me 的思路。

    第七节：AI 提效小工具 —— 框架逆向：代码库透视 + System Prompt 提炼（10 min，选学）¶

    配套资产：TOOL-framework-reverse（两段式 Prompt 原文 + 使用说明）

    它解决什么问题¶

    接手一个陌生框架时有两个痛点：读懂慢（通读代码库搞清技术栈、目录职责、执行流程，动辄几天）和留不住（读懂了，经验只在脑子里，换个项目又重来）。本工具用两段式 Prompt 流水线一次解决 —— 先透视、再蒸馏。

    两步流水线¶

    代码库 → [Step 1 透视] → 项目理解报告 → [Step 2 蒸馏] → 通用 System Prompt（团队资产）
    • Step 1「快速了解框架关键信息」：AI 以资深架构师身份只读审查整个代码库，输出技术栈、目录职责、入口与执行流（上下游 / 输入输出）、系统类型、潜在问题五步总结。可独立用于新人 onboarding。
    • Step 2「逆向提炼通用 System Prompt」：在 Step 1 的上下文基础上，逆向提炼架构分层（每层职责）与工程规范（安全 / 健壮性 / 日志 / 输出格式），整合成一份可直接复制给 AI 使用的 System Prompt，业务细节全部抽象为 [填空变量]，并附两个场景示例。

    提示词骨架（完整原文见配套资产 prompt.md）：

    Step 1：你是资深 Python 自动化测试平台架构师。请仔细阅读整个代码库，
       不要修改任何代码，用中文总结：核心技术栈 / 目录结构职责 /
       入口与核心执行流程 / 系统类型 / 结构特点与潜在问题。

Step 2：你是资深 Python 自动化架构师。请逆向提炼该项目的
       架构分层标准 + 工程规范，整合成一份可直接使用的 System Prompt，
       业务细节抽象为 [填空变量]，附两个场景示例，输出 Markdown。

    与第五节的衔接¶

    Step 2 的产出正是第五节「今天就贡献一条」要的素材：评审通过后按第二节的标准模板格式贡献到团队 Prompt 库 —— 团队 Prompt 库从此多一条"从框架蒸馏"的稳定供给渠道。

    注意事项¶

    • 喂给 AI 的代码必须先脱敏（去密钥、去内部地址、去真实数据）；
    • 大仓库注意上下文窗口：IDE 类 AI 工具（可索引整个工作区）效果最好，对话式工具需分批喂；
    • AI 逆向出的规范 ≠ 项目真实规范，入库前对照代码抽查关键条目，防止 AI 把"它认为应该的"当成"项目实际的"。
