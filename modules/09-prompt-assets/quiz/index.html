    M9 测验 — Prompt 资产体系建设¶

    题目数量：6 题 | 建议时间：8 分钟 | 通过标准：4 题正确

    选择题（单选，每题 1 分）¶

    Q1. 一个 Prompt 模板"可用性"评分低（1–2分）最可能的原因是什么？

    • A. Prompt 太短
    • B. 新成员按照说明使用后，无法得到接近期望的输出
    • C. Prompt 使用了中文
    • D. 没有限制输出字数
    查看答案

    答案：B

    解析：可用性评分评估的是"可用程度"——新成员照着用，不需要额外知识，就能得到有用的输出。可用性低意味着 Prompt 依赖使用者的隐性知识（如特定背景、特定上下文），导致效果不稳定。

    Q2. 以下哪种做法最符合团队 Prompt 库的 GitHub 维护规范？

    • A. 直接修改 main 分支上的 Prompt 文件，立即生效
    • B. 在 Issue 中提出 Prompt 改进建议，经讨论后提交 PR，由另一名成员审查后合并
    • C. 每人维护一个个人 Prompt 文件，不合并到公共库
    • D. 每月清空旧 Prompt，重新收集
    查看答案

    答案：B

    解析：通过 Issue → 讨论 → PR → Review → 合并的流程，确保了：① 改动有记录；② 改动经过同行验证；③ 坏的改动可以 Revert；④ 团队对变化知情。直接修改 main 没有审查，个人维护无法共享，清空旧 Prompt 丢失知识资产。

    Q3. 一个 Prompt 被标记为"已知效果不佳的场景"，这意味着什么？

    • A. 这个 Prompt 质量太差，应该删除
    • B. 这个 Prompt 不适合任何场景
    • C. 这个 Prompt 在特定条件下表现不好，使用时需要注意这些限制
    • D. 这个 Prompt 需要立即被替换
    查看答案

    答案：C

    解析："已知局限"是 Prompt 质量的一部分——诚实记录边界条件，让用户知道在什么情况下需要调整 Prompt 或换用其他方法。有局限不等于没价值，在主要使用场景中有效的 Prompt 仍然值得保留。

    判断题（T/F，每题 1 分）¶

    Q4. 只有测试 Lead 或资深工程师才能向团队 Prompt 库贡献新模板。

    查看答案

    答案：F（错误）

    解析：任何团队成员都可以贡献 Prompt，包括初级工程师和手工测试人员。贡献流程（Issue → PR → Review）本身是质量保证机制，入库前需要经过同行验证，而不是依靠贡献者的资历来保证质量。

    Q5. 团队 Prompt 库一旦建立就不需要维护，可以永久使用。

    查看答案

    答案：F（错误）

    解析：Prompt 需要持续维护，因为：① AI 模型版本更新可能改变响应风格；② 业务场景和系统变化会让旧 Prompt 不再准确；③ 团队积累更多经验后可以优化已有 Prompt。建议每月 Review 一次，每季度做一次全量检查。

    简答题（1 题，5 分）¶

    Q6. 一名新加入团队的测试工程师问：我们有 Prompt 库，是不是直接用里面的模板就够了，不需要自己学 Prompt 写法了？请你给出你的回答（3–5 句话）。

    参考答案

    （评分标准：观点正确 2 分 + 论据充分 2 分 + 建议实用 1 分）

    参考回答：

    不能只依赖模板。Prompt 库提供的是"已验证的起点"，而不是所有场景的完整解决方案。

    真实工作中会遇到模板没有覆盖的新场景，这时候需要自己从五要素框架开始写 Prompt。理解 Prompt 工程的原理（角色 + 背景 + 任务 + 格式 + 约束）才能在模板不够用时进行调整，也才能识别出模板输出质量不好的根本原因。

    此外，使用模板时往往需要根据具体场景调整占位符内容——理解 Prompt 原理的人能把占位符填得更准确，输出质量更高。

    建议：先认真学完 M2 Prompt 工程精讲，再使用模板库，这样的组合效果最好。
