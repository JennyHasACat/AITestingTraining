    M3 — 测试用例 AI 批量生成¶

    时长：2 小时 | 受众：全员必修 | 前置要求：M1 + M2 完成

    学习目标¶

    完成本模块后，你能够： 1. 用 AI 从需求文档一键生成结构化测试用例初稿 2. 应用等价类划分和边界值分析的 Prompt 模板 3. 对 AI 生成的用例进行质量评审，识别不合理的条目 4. 通过多轮对话扩展用例覆盖面（分维度迭代） 5. 将 AI 输出导出为 CSV 格式（可导入测试管理系统）

    第一节：AI 用例生成的正确工作流（20 min）¶

    错误做法 ❌¶

    把整个需求文档粘贴给 AI → 期望一次性获得完美的用例集

    问题： - 输出质量随文档长度增加而下降 - AI 容易遗漏细节、混淆场景 - 生成后大量返工

    正确做法 ✅¶

    步骤 0：复杂 Story 先在 M5 使用 R-07 建立准入漏斗和路径清单
步骤 1：让 AI 先提取测试维度（不写用例）
步骤 2：按维度分批生成用例
步骤 3：追问边界值和异常场景
步骤 4：要求 AI 进行自检（检查遗漏）
步骤 5：人工 Review + 补充
步骤 6：导出 CSV

    为什么分步效果更好？¶

    一次性生成 分步生成
    容易遗漏细节 每步聚焦，遗漏更少
    格式可能不一致 格式统一，可直接使用
    覆盖深度浅 可针对每个维度深挖
    调整成本高 可逐步迭代优化

    对于包含多层业务规则的 Story，先带入 M5 的 R-07 输出：将 [JIRA_KEY-PATH-XX] 路径标识、准入条件和断言候选作为用例生成输入。路径标识用于需求追踪；这里生成的用例仍应使用测试管理工具规定的正式用例 ID。

    第二节：测试维度提取（20 min）¶

    Prompt 模板：测试维度提取¶

    你是一名有 8 年企业软件测试经验的测试架构师。
以下是一段功能需求描述：
[粘贴需求]

请帮我将这个功能的测试范围拆解为测试维度。
要求：
- 只列维度名称和简要说明，不要写具体用例
- 覆盖：功能逻辑、数据边界、权限控制、异常处理、界面交互、性能/并发（如适用）
- 输出格式：有序列表，每个维度 1–2 句话说明

    示例（登录功能）¶

    需求输入： 

    用户登录功能：支持邮箱+密码登录，密码错误3次锁定账号30分钟，
支持"记住我"（7天有效期），登录成功后跳转到仪表盘。

    AI 提取的维度： 

    1. 正常登录流程：有效邮箱+正确密码成功登录
2. 密码错误处理：1次、2次、3次错误后的系统响应
3. 账号锁定机制：锁定触发、锁定期间的状态、30分钟后自动解锁
4. "记住我"功能：勾选后7天内免密登录；不勾选时会话关闭后需重新登录
5. 输入格式验证：邮箱格式、密码字段（空值、特殊字符）
6. 跳转逻辑：登录成功后跳转目标页面的正确性
7. 安全场景：SQL注入、暴力破解防护
8. 会话管理：并发登录、会话超时

    第三节：分维度生成用例（30 min）¶

    Prompt 模板：单维度用例生成¶

    你是一名测试设计专家。
针对"[维度名称]"这个测试维度，功能背景是：[简要背景]
请设计测试用例，要求：
- 输出 Markdown 表格：用例ID | 场景描述 | 前置条件 | 操作步骤 | 预期结果 | 优先级
- 至少 [N] 条
- 每条用例的预期结果必须具体可验证（禁止"系统正常运行"此类模糊描述）
- 优先级：P0（主路径）/ P1（重要）/ P2（一般）

    追加覆盖：边界值专项¶

    上面的测试用例生成完毕后，请专门补充边界值测试：
- 对所有数字型、日期型、字符串长度型字段进行边界分析
- 每个字段给出：最小值-1、最小值、最大值、最大值+1 四个测试数据
- 格式同上

    第四节：AI 用例自检（10 min）¶

    生成完用例集后，发送以下 Prompt 让 AI 进行自检：

    请对上面生成的测试用例做一次自检，检查是否遗漏以下场景：
1. 并发/竞态条件
2. 跨角色权限场景（不同角色看到的结果是否不同）
3. 数据持久化（提交后刷新页面，数据是否正确保存）
4. 回滚/撤销场景
5. 国际化/多语言（如适用）

如果发现遗漏，请补充对应的测试用例（格式同上）。

    第五节：导出为 CSV（10 min）¶

    当用例表格生成完毕后，发送：

    请将上面所有测试用例整理成一个 CSV 格式输出，分隔符为英文逗号，
字段顺序：case_id,scenario,precondition,steps,expected_result,priority
第一行为表头，steps 字段中的换行用"；"代替

    这样可以直接导入 Jira Xray / TestRail / 禅道等测试管理工具。

    第六节：AI 提效小工具 —— 自动生成测试用例（10 min）¶

    待补充：具体工具 / 链接 / 进阶用法（由维护者持续更新）

    它解决什么问题¶

    前面学的是"用通用大模型聊天生成用例"。实际团队往往有专门封装好的工具/脚本：把需求文档或接口定义丢进去，直接产出结构化用例，省去每轮手动拼 Prompt。

    核心思路（伪步骤）¶

    1. 输入：需求文档 / 接口 Schema / 页面原型
2. 工具内部：调用大模型（套用团队已验证的用例生成 Prompt）
3. 输出：结构化用例（表格 / CSV / 直接写入用例库）

    提示词骨架（工具底层常封装的逻辑，可直接复用）：

    你是资深测试架构师。基于以下输入生成测试用例：
- 输入类型：[需求文本 / OpenAPI Schema / 页面元素清单]
- 覆盖要求：正常流程 + 边界值 + 异常 + 权限
- 输出格式：[Markdown 表格 / CSV]
- 业务规则来源：[粘贴的关键约束]
请先列测试维度，再按维度展开用例。

    注意事项¶

    • 工具输出仍需人工 Review（参考本章 Review 要点）；
    • 私有工具只写思路，不贴内部实现代码。

    第七节：AI 提效小工具 —— 一键上传测试用例（10 min）¶

    待补充：具体工具 / 链接 / 进阶用法（由维护者持续更新）

    它解决什么问题¶

    生成 CSV 后，还要手动登录测试管理系统（Jira Xray / TestRail / 禅道）逐条粘贴，耗时且易错。本工具思路是把 CSV 自动桥接到用例库，省去手工录入。

    核心思路（伪步骤）¶

    1. 准备：AI 生成的用例 CSV（字段与本章第五节一致）
2. 映射：工具读取 CSV 列 → 映射到目标系统的字段（case_id/scenario/...）
3. 上传：调用目标系统 API / 导入接口批量创建用例
4. 回执：返回创建成功的用例 ID，失败行单独报告

    提示词 / 配置骨架思路：

    你是一个测试管理助手。请把下面的 CSV 用例批量导入 [Jira Xray / TestRail / 禅道]：
- 认证：[从环境变量读取 API Token，不硬编码]
- 字段映射：case_id→测试编号，scenario→摘要，steps→步骤，expected_result→预期
- 冲突处理：若编号已存在则跳过并报告
- 输出：成功数 / 跳过数 / 失败明细

    注意事项¶

    • 上传前确认目标项目的用例层级（模块 / 套件）已建好；
    • 敏感环境用只读账号或测试项目先试跑；
    • 私有实现只写思路，课件不贴内部脚本。

    第八节：人工 Review 要点（10 min）¶

    AI 生成的用例必须经过人工审查，重点检查：

    检查项 常见问题
    预期结果是否可验证 出现"系统正常运行"等模糊描述
    步骤是否完整 缺少前置数据准备步骤
    业务规则是否正确 AI 可能猜测规则而非依据需求
    用例是否重复 分批生成时可能出现重复场景
    优先级是否合理 AI 的优先级判断不了解业务重要性
    测试数据是否合理 AI 生成的测试数据可能不符合系统约束

    人工 Review 的黄金原则：每条用例你都应该能回答"这条用例测的是什么业务规则？如果失败，会影响什么？"

    第九节：AI 提效小工具 —— 思维导图 TXT 转 MD（XMind 导入）（10 min，选学）¶

    工具 ID：TOOL-emmx2md ｜ 索引：AI 提效工具箱 ｜ 脚本：仓库 tools/emmx-to-md/

    它解决什么问题¶

    用 AI 生成测试用例时，思维导图是常见的中间产物（结构清晰、方便评审）。但亿图 / XMind 之间格式不互通：亿图导出的 TXT 用 Tab 缩进表示层级，XMind 只吃 Markdown 大纲，手动转换 100+ 节点的导图既慢又容易丢内容。本工具补齐工具链的中间环节：AI 生成思维导图用例 → 亿图导出 TXT → 转 MD → 导入 XMind 评审 / 编辑 → CSV 上传用例库。

    核心思路 / 提示词骨架¶

    1. 输入：亿图思维导图导出的 .txt（Tab 缩进表层级）
2. 解析：按缩进建树；识别"顶格续行"合并回上一节点（亿图多行节点的坑）
3. 序列化：输出 Markdown 无序列表（每层 2 空格），XMind 可直接导入
4. 护栏：与原 TXT 做字符级保真比对（去空白后逐字一致 = 0 丢字），出转换报告

    让 AI 生成此类格式转换脚本，提示词关键要素（完整版见仓库 tools/emmx-to-md/prompt.md）：

    1. 核心约束放最前：「保留原文所有内容，一个字都不能丢」
    2. 讲清输入陷阱：附真实样例，点明"多行节点续行顶格无缩进"这个坑
    3. 锁死输出决策：标注「已确定，不要改」——如用列表不用标题（标题最多 6 层，本例最深 8 层）
    4. 要求自证护栏：字符级保真比对（txt 去空白 vs md 去标记，SequenceMatcher 算相似度）
    5. 给出验证标准：转换真实样本，确认续行合并 + 保真率 100%

    使用示例¶

    python emmx_to_md.py "OMNI-69499.txt"          # 单文件
python emmx_to_md.py ./txts -o ./md_out        # 批量目录
python emmx_to_md.py ./txts --dry-run          # 只校验不写盘

    注意事项¶

    • 保真比对是核心护栏：报告保真率必须 100%，出现 ⚠️（孤立行 / 编码替换字符 U+FFFD）需人工核对；
    • 编码混乱的 TXT（GBK/UTF-8 混存）建议先 --dry-run 探一遍再正式转；
    • 工具脚本与生成它的 Prompt 本身就是团队资产，应纳入 M9 的资产管理流程。

    本模块小结¶

    步骤 关键 Prompt 输出物
    维度提取 模板：测试维度提取 测试维度清单
    分批生成 模板：单维度用例 分维度用例表格
    边界补充 边界值专项追问 边界值用例
    自检 AI 自检 Prompt 遗漏场景补充
    导出 CSV 格式 Prompt 可导入的 CSV 文件
    人工审查 6 项 Review 要点 最终确认用例集
