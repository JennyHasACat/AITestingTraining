    Prompt 模板资产包 — 测试报告与文档类¶

    分类：报告撰写 + 文档整理 | 适用模块：M5 + M10

    D-05 测试总结报告生成¶

    场景：迭代结束后快速生成测试总结报告
    推荐工具：Kimi / 通义千问
    效果评级：⭐⭐⭐⭐⭐
    最后验证日期：2026-07-20

    你是一名测试管理专家，擅长撰写清晰的测试总结报告。
以下是本次迭代的测试数据：
- 执行用例总数：[N]
- 通过：[N] / 失败：[N] / 阻塞：[N] / 跳过：[N]
- 发现缺陷总数：[N]（P0：[N]，P1：[N]，P2：[N]，P3：[N]）
- 已修复并验证：[N]
- 遗留缺陷：[列出主要遗留 Bug]
- 测试范围：[描述]
- 未测试范围：[描述]
- 遗留风险：[描述]
请生成适合发给项目经理和研发 Lead 的测试总结报告（中文），
格式：概述 → 数据摘要 → 缺陷分析 → 遗留风险 → 测试结论 → 建议
语气：客观专业，数据驱动。

    D-01 ROI 管理层汇报摘要¶

    场景：向 CTO / 业务负责人汇报 AI 辅助测试的价值
    推荐工具：Kimi / 通义千问
    效果评级：⭐⭐⭐⭐⭐
    最后验证日期：2026-07-20
    重要提醒：使用真实数据，不要夸大，诚实汇报局限性

    你是一名测试管理专家，擅长向业务领导汇报效率提升。
AI 辅助测试试点数据（[N] 周）：
- 参与人数：[N]人
- 用例编写速度：提升约 [X]%（样本：[N] 次记录）
- 脚本生成时间：缩短约 [X]%
- Bug 报告规范化：缩短约 [X]%
- 工具成本：[GitHub Copilot N元/人/月，国产工具免费]
- 局限性：[诚实说明哪些环节提升不明显]
请生成 2 页以内的管理层汇报摘要（中文），包含：
1. 执行摘要（结论先行，2-3句话）
2. 关键数据亮点（数字为主）
3. 投入产出分析（12个月 ROI 估算）
4. 下一步建议（具体 3 条，可量化）
语气：数据驱动，专业客观，不过度承诺。

    D-02 Sprint Bug 分析报告¶

    场景：每个 Sprint 结束时分析缺陷模式，输入下轮改进
    推荐工具：通义千问
    效果评级：⭐⭐⭐⭐
    最后验证日期：2026-07-20

    你是一名测试数据分析专家。
以下是本 Sprint 发现的所有 Bug 列表（已分类）：
[粘贴 Bug 列表，包含：标题/模块/严重程度/根因类型]
请分析：
1. 缺陷分布（按模块/严重程度/根因类型）
2. 前 3 个高频根因及可能的预防措施
3. 与上个 Sprint 相比，有没有改善或新出现的问题模式
4. 对下个 Sprint 测试策略的建议（1-2 条）
输出：图表描述 + 文字分析，适合在 Sprint 回顾会议上展示

    D-03 测试用例评审报告¶

    场景：测试用例评审后，快速生成评审纪要
    推荐工具：任意
    效果评级：⭐⭐⭐
    最后验证日期：2026-07-20

    以下是一次测试用例评审会议的讨论要点（笔记形式）：
[粘贴你的会议笔记]
请整理成正式的评审纪要，包含：
- 参与人员 / 时间 / 被评审内容
- 审查通过的用例数量
- 需要修改的用例（列表，每条说明修改原因）
- 新增用例的要求
- 下一步 Action（谁 / 做什么 / 什么时候）
格式：Markdown，可直接发邮件或贴 Confluence

    推荐工具：DeepSeek
    效果评级：⭐⭐⭐⭐
    最后验证日期：2026-07-20

    你是一名 API 测试专家。
以下是[模块名]的 API 文档摘要（接口列表 + 关键参数）：
[粘贴 API 文档概要]
以下是当前已有的 API 测试用例覆盖（简要描述）：
[粘贴现有用例列表]
请分析：
1. 哪些接口完全未被测试覆盖
2. 哪些接口只测试了正向场景（缺少错误场景）
3. 哪些高风险接口（数据写操作/权限控制）覆盖不足
4. 建议优先补充的 5 个测试场景
