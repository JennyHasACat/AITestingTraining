## B-01 日志根因分析（通用）

**场景**：将报错日志发给 AI 进行结构化根因分析  
**推荐工具**：DeepSeek（代码推理最准确）  
**效果评级**：⭐⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
你是一名资深 SDET，擅长 [Python/Java/JavaScript] 调试和日志分析。
以下是一段测试运行时的报错：
[粘贴完整报错日志，包括 traceback]
环境：[框架版本 + 语言版本 + 浏览器]
请按步骤分析：
1. 识别报错类型和触发位置（文件名 + 行号）
2. 列出 3 个最可能的根本原因，按可能性从高到低排序
3. 每个假设给出最快验证方法（1-2 步操作）
4. 给出最终修复建议
```

## B-02 Playwright UI 失败分析

**场景**：专门针对 Playwright 自动化测试失败的分析  
**推荐工具**：DeepSeek  
**效果评级**：⭐⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
你是一名 Playwright Python 自动化测试专家。
测试名称：[test_xxx]
失败步骤：[在哪一步出错]
报错信息：[错误类型和消息]
页面状态：[描述截图中的页面状态]
业务上下文：[被测功能的简要说明]
请分析：
1. 最可能的 3 个根因（选择器失效/元素未加载/超时/数据问题/环境问题）
2. 如何用最少步骤验证假设
3. 如果是选择器问题，推荐更稳健的选择器策略
4. 建议的修复方向（修改定位器/增加等待/数据准备）
```

## B-04 Bug 报告规范化生成

**场景**：将口头描述或零散记录转化为规范 Bug 报告  
**推荐工具**：Kimi / 通义千问  
**效果评级**：⭐⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
你是一名测试工程师，需要填写一份规范的 Bug 报告。
以下是我对这个 Bug 的描述（可能不完整）：
[自然语言描述 Bug 现象]
环境：[浏览器/OS/测试环境]
严重程度（我的判断）：[P0/P1/P2/P3]
请生成完整 Bug 报告，包含：
标题（格式：[模块名] [操作] [错误现象]）、严重程度、复现率、环境、
前置条件、复现步骤（具体可独立复现）、预期结果、实际结果。
要求：复现步骤必须让没有上下文的开发人员能独立复现。
```
