## DB-01 UI 提交后数据验证 SQL

**场景**：UI 功能测试后，验证数据是否正确存入数据库  
**推荐工具**：DeepSeek（SQL 推理准确）  
**效果评级**：⭐⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
你是一名数据库测试专家，数据库类型：[MySQL/PostgreSQL]。
我完成了[功能名称]的 UI 测试，需要在数据库层面验证数据存储正确。
表结构：
[粘贴 CREATE TABLE 语句或字段列表]
提交的测试数据：
[字段名: 值 的列表]
请生成 SELECT 查询，验证：
1. 记录是否存在
2. 关键字段值是否与提交值一致
3. 系统自动填充字段（创建时间、默认状态）是否正确
注意：只生成 SELECT，不要生成任何写操作。
```

## DB-02 测试数据 Setup + Teardown

**场景**：为特定测试场景准备数据，并在测试后清理  
**推荐工具**：DeepSeek  
**效果评级**：⭐⭐⭐⭐  
**最后验证日期**：2026-07-20  
**已知局限**：复杂的外键关系可能需要人工调整顺序

```
你是一名测试数据工程师，数据库类型：[MySQL/PostgreSQL]。
测试场景：[描述你需要的数据状态，如"一个 30 分钟前被锁定的账号"]
相关表：[表名 + 关键字段]
请生成：
1. INSERT/UPDATE 语句（Setup，创建所需数据状态）
2. 验证 SELECT（确认数据已正确创建）
3. DELETE/UPDATE 清理语句（Teardown）
安全要求：
- INSERT 的标识字段（如 email/username）必须含 "TEST_" 前缀
- DELETE 必须有精确的 WHERE 条件，不允许裸 DELETE FROM 表名
- 提供执行顺序说明
```

## DB-04 Salesforce SOQL 查询生成（OmniPeople 专用）

**场景**：在 Salesforce/OmniPeople 中验证 Object 数据  
**推荐工具**：DeepSeek  
**效果评级**：⭐⭐⭐⭐  
**最后验证日期**：2026-07-20  
**已知局限**：不支持 SELECT *，必须列出字段；不支持 JOIN（用关系字段导航）

```
你是一名 Salesforce 测试专家，熟悉 SOQL。
我需要验证 [Object 名称] 中的数据是否正确。
Object 字段：[字段名1, 字段名2, ...]（列出需要验证的字段）
筛选条件：[如：Email = 'test@test.com'，且 CreatedDate 在最近 1 小时内]
请生成 SOQL 查询。
注意：
- SOQL 不支持 SELECT *，必须列出所有需要的字段
- 多表关联使用关系字段导航（如 Account.Name）
- 日期函数使用 LAST_N_HOURS:1 或 TODAY 等 SOQL 专用语法
```

## DB-05 测试数据快速生成（大批量）

**场景**：需要生成多条不同状态的测试数据时

**效果评级**：⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
你是一名测试数据工程师，数据库类型：[MySQL]。
我需要为测试环境生成 [N] 条[数据类型]的测试记录，
涵盖以下状态：[状态1, 状态2, 状态3]。
表结构：[提供关键字段]
请生成批量 INSERT 语句：
- 每条记录有唯一标识（email/username 含 TEST_AUTO_ 前缀 + 序号）

```
