**最后验证日期**：2026-07-20

```
你是一名测试管理专家，擅长撰写清晰的测试总结报告。
以下是本次迭代的测试数据：
- 执行用例总数：[N]
- 通过：[N] / 失败：[N] / 阻塞：[N] / 跳过：[N]
- 发现缺陷总数：[N]（P0：[N]，P1：[N]，P2：[N]，P3：[N]）

## D-01 ROI 管理层汇报摘要

**场景**：向 CTO / 业务负责人汇报 AI 辅助测试的价值  
**推荐工具**：Kimi / 通义千问  
**效果评级**：⭐⭐⭐⭐⭐  
**最后验证日期**：2026-07-20  
**重要提醒**：使用真实数据，不要夸大，诚实汇报局限性

```
你是一名测试管理专家，擅长向业务领导汇报效率提升。
AI 辅助测试试点数据（[N] 周）：
- 参与人数：[N]人
- 用例编写速度：提升约 [X]%（样本：[N] 次记录）
- 脚本生成时间：缩短约 [X]%
- Bug 报告规范化：缩短约 [X]%
- 工具成本：[GitHub Copilot N元/人/月，国产工具免费]
- 局限性：[诚实说明哪些环节提升不明显]
请生成 2 页以内的管理层汇报摘要（中文），包含：
1. 执行摘要（结论先行，2-3句话）
2. 关键数据亮点（数字为主）
3. 投入产出分析（12个月 ROI 估算）
4. 下一步建议（具体 3 条，可量化）
语气：数据驱动，专业客观，不过度承诺。
```

## D-02 Sprint Bug 分析报告

**场景**：每个 Sprint 结束时分析缺陷模式，输入下轮改进  
**推荐工具**：通义千问  
**效果评级**：⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
你是一名测试数据分析专家。
以下是本 Sprint 发现的所有 Bug 列表（已分类）：
[粘贴 Bug 列表，包含：标题/模块/严重程度/根因类型]
请分析：
1. 缺陷分布（按模块/严重程度/根因类型）
2. 前 3 个高频根因及可能的预防措施
3. 与上个 Sprint 相比，有没有改善或新出现的问题模式
4. 对下个 Sprint 测试策略的建议（1-2 条）
输出：图表描述 + 文字分析，适合在 Sprint 回顾会议上展示
```

```
