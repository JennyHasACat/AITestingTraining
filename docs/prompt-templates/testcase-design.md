## T-01 功能测试用例生成（通用）

**场景**：从功能需求描述生成结构化测试用例  
**推荐工具**：Kimi / 通义千问  
**效果评级**：⭐⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
你是一名有[工作年限]年[系统类型]测试经验的高级测试工程师。
功能描述：[粘贴需求描述，2-5句话即可]
请设计测试用例，覆盖：
1. 正常流程（Happy Path）
2. 边界值
3. 异常/错误输入
4. 权限控制（如适用）
输出：Markdown 表格，列：用例ID | 场景描述 | 前置条件 | 操作步骤 | 预期结果 | 优先级（P0/P1/P2）
至少 [N] 条，必须包含 [指定关键场景]。
预期结果必须具体可验证，禁止出现"系统正常运行"此类模糊描述。
```

**使用说明**：替换 `[]` 占位符。`工作年限` 填 5–10 年效果最好。

## T-02 测试维度提取（大模块分析）

**场景**：对复杂功能先提取维度，再分批生成用例  
**推荐工具**：Kimi（长文档），DeepSeek（逻辑推理）  
**效果评级**：⭐⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
你是一名测试架构师。
以下是[功能名称]的完整需求描述：
[粘贴需求]
请提取所有测试维度（不写具体用例，只列维度名称和简要说明）。
覆盖：功能逻辑、数据边界、权限控制、异常处理、界面交互、性能/并发（如适用）。
格式：有序列表，每条 1-2 句话说明。
```

## T-03 边界值专项补充

**场景**：为已生成的用例集补充边界值测试点  
**推荐工具**：DeepSeek  
**效果评级**：⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
上面的用例生成完毕后，请专项补充边界值测试：
- 对所有数字型、日期型、字符串长度型字段进行边界分析
- 每个字段给出：最小值-1、最小值、最大值、最大值+1 四个数据点
- 每个数据点说明期望结果（有效/无效 + 具体表现）
- 格式同上（Markdown 表格）
```

## T-04 AI 自检（遗漏场景检测）

**场景**：用例生成完毕后，让 AI 检查是否遗漏重要场景  
**推荐工具**：任意  
**效果评级**：⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
请对上面生成的测试用例做一次自检，检查是否遗漏以下场景：
1. 并发/竞态条件
2. 跨角色权限场景
3. 数据持久化（提交后刷新/重启）
4. 回滚/撤销场景
5. 国际化/多语言（如适用）
6. 网络异常/超时场景
如果发现遗漏，请补充对应用例（格式同上）。
```

## T-05 CSV 导出

**场景**：将 Markdown 表格转换为可导入测试管理工具的 CSV  
**推荐工具**：任意  
**效果评级**：⭐⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
请将上面所有测试用例整理成 CSV 格式，
字段顺序：case_id,scenario,precondition,steps,expected_result,priority
第一行为表头，steps 字段中的换行用"；"代替，
所有字段用英文逗号分隔，文本字段用英文双引号包裹。
```

## T-06 优先级决策辅助

**场景**：时间有限时，快速决定哪些用例优先执行  
**推荐工具**：DeepSeek（推理准确）  
**效果评级**：⭐⭐⭐⭐  
**最后验证日期**：2026-07-20

```
我有以下 [N] 个测试场景，只有时间执行 [M] 个。
[列出所有场景]
请按步骤分析：
1. 判断每个场景的风险级别（高/中/低），说明理由
2. 识别主路径场景（不测会阻断其他用例的）
3. 考虑业务影响（到达生产环境的后果）
4. 给出最终建议：优先执行哪 [M] 个，跳过哪些，为什么
```

## OP-T01 OmniPeople New Hire 用例生成

**场景**：专门用于 OmniPeople New Hire 场景的测试用例生成  
**推荐工具**：Kimi  
**效果评级**：⭐⭐⭐⭐  
**最后验证日期**：2026-07-20  
**已知局限**：对 Salesforce 特有的 Flow/Trigger 行为理解有限

```
你是一名 HR 系统测试专家，熟悉 Salesforce 平台。
我正在测试 OmniPeople 系统的新员工入职（New Hire）流程：
- 员工类型：[全职 Full-time / 兼职 Part-time]
- 合同类型：[Standard / NonPromoter / Promoter / RedBook]
- 雇佣主体：[BU / 其他]
请设计测试用例，覆盖：字段验证、条件显示逻辑、日期边界、权限控制、数据一致性。
输出：Markdown 表格，列：用例ID | 场景 | 前置条件 | 步骤 | 预期结果 | 优先级
至少 10 条，必须包含分支逻辑（选择不同类型时的字段变化）。
```
