# M1 实战 Lab — OmniPeople 定制版：AI 工具初体验

> **预计时长**：30–40 分钟 | **工具**：Kimi / DeepSeek / 通义千问（任选）  
> **适用场景**：OmniPeople 系统测试团队

---

## 前置条件

- [ ] 已完成 M1 课件阅读
- [ ] 至少一个 AI 工具账号可正常使用
- [ ] 了解 OmniPeople 系统（Manager Service / New Hire 流程基础知识）

## Lab 1-A：OmniPeople New Hire 场景头脑风暴（15 min）

### 背景说明

OmniPeople 系统中的 **New Hire 入职流程** 包含多个业务场景，例如：
- 全职（Full-time）vs 兼职（Part-time）
- 不同雇佣单位（BU / NonPromoter / Promoter）
- 不同地区（China / MCN / EFO 等）
- 不同合同类型（Standard / Redbook 等）

### 步骤

发送以下 Prompt 给 AI：

```
你是一名资深测试工程师，熟悉 HR 系统测试。
我正在测试一个新员工入职系统（New Hire），该系统需要处理以下情况：
- 员工类型：全职（Full-time）、兼职（Part-time）
- 雇佣主体：BU 内部、NonPromoter 外部合作伙伴
- 合同生效时间、职位信息、薪资等字段

请帮我从以下角度挖掘测试场景：
1. 必填字段验证
2. 不同员工类型的分支逻辑差异
3. 日期边界（入职日期过去/未来/当天）
4. 权限控制（谁可以创建/审批）
5. 数据一致性（提交后数据库记录是否正确）

每个角度列出 3–4 个测试点，不需要写详细步骤。
```

---

### 反思问题

1. AI 生成的测试点中，有哪些是你们现有测试用例中已经覆盖的？
2. 有哪些是你们过去可能忽略的（特别是权限和数据一致性方向）？
3. AI 对 OmniPeople 特有的业务术语（如 BU / NonPromoter）是否理解准确？如何改进 Prompt？

## Lab 1-B：AI 输出质量快速验证（10 min）

### 场景

假设 AI 给你生成了一条测试场景：
> "测试兼职员工入职时，合同结束日期早于开始日期，系统应报错"

### 步骤

1. **验证这条用例的合理性**：该场景在 OmniPeople 中是否真实存在？系统是否有这个校验？
2. 如果你不确定，继续追问 AI：

```
针对上面的场景，请帮我写出具体的测试步骤和预期结果，
假设系统使用前端表单提交，有日期选择器控件。
```

3. 评估 AI 给出的步骤是否可以直接执行，还是需要调整。

---

## Lab 1-C：AI 辅助测试场景优先级决策（10 min）

### 目标

用 AI 帮你做 **测试优先级排序**，节省评估时间。

### 步骤

将你在 Lab 1-A 中得到的测试场景列表，连同以下 Prompt 发送给 AI：

```
以下是我的测试场景列表：
[粘贴 Lab 1-A 的输出]

请根据以下标准对这些场景进行优先级划分：
- P0（阻断性）：影响主流程无法继续
- P1（高）：影响核心功能但有绕过方法
- P2（中）：影响非核心功能
- P3（低）：UI/提示文案类问题

输出格式：原场景描述 | 建议优先级 | 理由（一句话）
```

---

### 交付物

将优先级表格保存，作为后续 M3（测试用例生成）模块的练习材料。
