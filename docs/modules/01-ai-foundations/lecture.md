# M1 — AI 认知基础 + 工具环境搭建

> **时长**：1.5 小时 | **受众**：全员必修 | **前置要求**：无

---

## 学习目标

完成本模块后，你能够：
1. 用自己的话解释 LLM 是什么、能做什么、不能做什么
2. 识别「AI 会取代测试人员」等常见误区
3. 在自己的电脑上完成至少一个 AI 工具的账号注册 + 首次对话
4. 说出影响 AI 输出质量的 3 个核心因素

---

## 第一节：AI 为什么正在重塑测试工作？（15 min）

### 背景

过去 10 年，测试行业经历了：
```
手工测试 → 脚本自动化 → 框架驱动 → 现在：AI 辅助
```

AI 不是新的测试框架，而是一个**跨工作环节的放大器**：
- 写用例：从 2 小时 → 20 分钟
- 分析 Bug：从猜测 → 结构化根因假设
- 写脚本：从空白页 → 可运行初稿

### 人机协同模型

```
人负责：想清楚需求、判断质量、做决策
AI 负责：生成内容、代码补全、格式转换、信息检索
```

> **关键认知**：AI 的输出质量 = 你给的信息质量。垃圾进，垃圾出。

## 第二节：AI 大模型基础知识（20 min）

### 核心术语速查

| 术语 | 一句话解释 | 测试场景关联 |
|------|-----------|-------------|
| **LLM** | 大语言模型，通过海量文本训练的 AI | 我们用它生成用例、分析 Bug |
| **Prompt** | 你给 AI 的输入指令 | 写好 Prompt = 写好需求规格 |
| **Token** | AI 处理文本的最小单位（约 1 个中文字 = 1.5 token） | 影响长文档是否能完整处理 |
| **Context Window** | 单次对话能记住的最大内容量 | 超出后 AI 会"忘记"早期内容 |
| **Temperature** | 控制输出随机性（0 = 确定，1 = 创意） | 生成用例时建议 0.2–0.5 |
| **RAG** | 检索增强生成，让 AI 读你的文档再回答 | 可用于私有知识库问答 |

### 主流工具对比（团队可用）

| 工具 | 特点 | 测试团队使用场景 | 访问方式 |
|------|------|----------------|---------|
| **Kimi** | 长文档处理强，中文出色 | 需求文档分析、用例生成 | kimi.moonshot.cn |
| **DeepSeek** | 代码能力强，推理准确 | 脚本生成、SQL 编写、Bug 分析 | chat.deepseek.com |
| **通义千问** | 阿里出品，企业集成好 | 批量用例生成、报告撰写 | tongyi.aliyun.com |
| **GitHub Copilot** | IDE 内嵌，实时代码补全 | Playwright/pytest 脚本编写 | VS Code 插件 |

> ⚠️ **数据安全提醒**：不要将公司代码、用户数据、生产环境配置粘贴到公有云 AI。测试脚本框架和逻辑可以，真实密码/API Key 不行。

## 第三节：AI 的能力边界（15 min）

### AI 擅长的任务 ✅

- 文本生成 / 改写（用例描述、Bug 报告）
- 代码补全（脚本初稿、SQL 查询）
- 格式转换（把步骤转成 CSV、把日志转成结构化分析）
- 总结归纳（长文档提取测试点）
- 模式识别（日志中的错误模式）

### AI 不可靠的场景 ⚠️

- 精确数学计算（数据验证还需写断言）
- 实时数据（今天的接口状态 AI 不知道）
- 复杂业务规则判断（AI 会猜，需要人 Review）
- 动态 UI 选择器（AI 生成的 class/id 往往不稳定）

### AI 不能替代的 ❌

- 探索性测试的直觉判断
- 复杂业务场景的测试策略设计
- 对"这个测试够不够"的最终决策

## 第四节：工具环境搭建（30 min）

### 任务 1：注册至少一个 AI 工具账号

**推荐顺序**（按上手难度）：

1. **Kimi**（最快注册，中文最顺滑）
   - 打开 https://kimi.moonshot.cn/
   - 手机号注册 → 验证 → 直接开始

2. **DeepSeek**（代码能力最强，本模块 Lab 推荐使用）
   - 打开 https://chat.deepseek.com/
   - 邮箱注册 → 验证 → 开始使用

3. **GitHub Copilot**（IDE 内嵌，自动化工程师优先配置）
   - VS Code → Extensions → 搜索 `GitHub Copilot` → Install
   - 需要 GitHub 账号 + 订阅（或公司企业版授权）

### 任务 2：发送你的第一条测试相关 Prompt

打开任意 AI 工具，粘贴以下内容发送：

```
你是一名资深测试工程师。
我需要测试一个"用户登录"功能，请帮我列出 5 个测试场景（包含正向和负向）。
每个场景用一句话描述即可。
```

观察：
- AI 给出了什么？
- 有没有你没想到的场景？
- 有没有遗漏重要场景？

## 第五节：AI 辅助测试工作流全景（10 min）

```
需求文档
    ↓ [AI 提取测试点]
测试用例初稿
    ↓ [AI 补充边界/负向场景]
人工 Review 确认
    ↓
执行 / 自动化脚本生成 [AI 生成初稿]
    ↓
Bug 分析 [AI 辅助根因分析]
    ↓
测试报告 [AI 生成报告框架]
    ↓
管理汇报 [AI 量化提效数据]
```

> 本课程的 10 个模块对应这条链路上的每个环节。
