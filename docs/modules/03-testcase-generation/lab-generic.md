### 需求描述

```
功能名称：用户密码修改
系统类型：Web 应用，前后端分离
需求说明：
- 已登录用户可在"账号设置"页面修改密码
- 必须输入当前密码（旧密码）才能修改
- 新密码规则：8–20 位，必须包含大写字母、小写字母、数字三类字符
- 新密码和确认新密码必须一致
- 新密码不能与最近 3 次使用过的密码相同
- 修改成功后自动注销，要求重新登录
- 密码输入框支持"显示/隐藏密码"切换图标
```

## Lab 3-B：快速识别低质量用例（10 min）

以下 5 条 AI 生成的用例存在问题，请指出每条的问题所在：

| 用例 | 问题描述 |
|------|---------|
| 预期结果："系统正常处理用户请求" | |
| 场景："测试密码功能" | |
| 步骤：只有"点击保存" | |
| 新密码输入"12345678"，预期结果"修改成功" | |
| 优先级：P0 被标注为"密码框占位符文字验证" | |

<details>
<summary>参考答案</summary>

1. 预期结果模糊，无法验证 — 应改为"页面显示'密码修改成功'提示，自动跳转到登录页"
2. 场景描述过于笼统，无法确定测什么 — 应改为"修改密码时新旧密码相同时的系统响应"
3. 步骤不完整，缺少前置数据和操作上下文 — 应包含"进入账号设置页面 → 填写旧密码 → 填写新密码"
4. 测试数据不符合规则（只有数字，缺少大写字母）— AI 未遵循密码复杂度规则，此用例应被拒绝/修正
5. 优先级过高 — 占位符文字验证属于 P2/P3，非阻断性问题

</details>
