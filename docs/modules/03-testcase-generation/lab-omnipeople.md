# M3 实战 Lab — OmniPeople 定制版：New Hire 用例批量生成

> **预计时长**：50 分钟 | **工具**：Kimi / DeepSeek

---

## 背景

本 Lab 使用 OmniPeople 系统 **New Hire - Part Time BU NonPromoter** 场景作为练习材料。这是团队实际自动化测试覆盖的真实业务场景。

---

## Lab 3-A：New Hire Part-Time 用例维度提取（10 min）

发送以下 Prompt：

```
你是一名 HR 系统测试专家。
以下是一个新员工入职系统（New Hire）的业务场景：
- 员工类型：兼职（Part-time）
- 雇佣主体：BU 内部，NonPromoter 类型
- 需要填写的核心字段包括：
  员工姓名、邮箱、入职日期、职位名称、雇佣单位（BU）、
  合同类型（NonPromoter）、预计每周工时（1–40小时）、薪资级别、直属上级

请提取这个场景的所有测试维度（不写用例，只列维度）。
必须覆盖：字段验证、条件显示逻辑、日期边界、权限控制、数据一致性。
```

记录维度输出，供后续步骤使用。

---

## Lab 3-B：分批生成用例（25 min）

### 维度 1：预计每周工时字段验证

```
针对"预计每周工时"字段，约束规则为：
- 数字类型，范围 1–40
- 兼职员工必填
- 不允许小数

请设计边界值和等价类测试用例：
输出 Markdown 表格：用例ID | 输入值 | 预期结果 | 优先级
覆盖：有效范围内/边界值/超出范围/小数/零/负数/空值/字母输入
```

---

### 维度 2：入职日期验证

```
针对"入职日期"字段：
- 日期选择器类型
- 不能早于今天（当前系统日期）
- 不能超过 180 天后

请设计测试用例，覆盖：
- 今天（边界）
- 明天（有效）
- 昨天（无效）
- 180 天后（边界）
- 181 天后（无效）
- 空值

输出格式：同上，增加"前置条件"列
```

---

### 维度 3：BU NonPromoter 与 Promoter 的分支逻辑

```
在 New Hire 流程中，选择"NonPromoter"和"Promoter"合同类型时，
系统显示的字段不同（NonPromoter 显示字段 A、B、C；Promoter 显示字段 D、E）。

请设计测试用例验证：
1. 选择 NonPromoter 时，字段 A/B/C 显示，D/E 隐藏
2. 选择 Promoter 时，字段 D/E 显示，A/B/C 隐藏
3. 切换合同类型时，已填写的数据是否被清空
4. 默认选中状态

输出：同上格式
```

## Lab 3-C：导出并与现有 YAML 对比（15 min）

### 步骤 1：导出 CSV

将上面所有生成的用例合并，发送 CSV 导出 Prompt，获得 CSV 格式用例。

### 步骤 2：对比现有自动化用例

打开项目中的 `fixtures/omniPeople/managerService/newHire/` 目录，找到 Part-Time 相关的 YAML 文件。
