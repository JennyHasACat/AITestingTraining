# M2 — Prompt 工程精讲

> **时长**：2 小时 | **受众**：全员必修 | **前置要求**：M1 完成

---

## 学习目标

完成本模块后，你能够：
1. 使用"角色 + 背景 + 任务 + 格式 + 约束"五要素结构写出有效 Prompt
2. 应用 Few-shot（少样本）技巧让 AI 对齐你的输出风格
3. 使用 Chain-of-Thought（思维链）提升 AI 的复杂推理准确性
4. 将长任务拆解为多轮对话，避免上下文超限导致质量下降
5. 识别并修复团队中常见的低效 Prompt 模式

---

## 第一节：Prompt 五要素框架（30 min）

### 基础公式

```
[角色设定] + [背景上下文] + [具体任务] + [输出格式要求] + [约束条件]
```

每个要素缺失都会降低输出质量。下面逐一说明。

---

### 要素 1：角色设定

**作用**：激活 AI 相关的"知识领域"，输出更专业。

| 弱版本 | 强版本 |
|--------|--------|
| 帮我分析这个 Bug | 你是一名有 10 年 Java 后端开发经验的 SDET，擅长日志分析和根因定位 |
| 写测试用例 | 你是一名熟悉 HR 系统测试的高级测试工程师，了解中国劳动法合规要求 |

**技巧**：角色越具体（工作年限 + 技术栈 + 行业），输出越精准。

---

### 要素 2：背景上下文

**作用**：消除 AI 的猜测，让它在正确的语境下工作。

**测试场景常用背景信息**：
- 系统类型（Web / App / API / 桌面）
- 当前测试阶段（功能测试 / 回归 / UAT）
- 已知约束（浏览器兼容性要求、数据库类型、框架版本）
- 相关业务规则（如需）

**示例**：
```
背景：我们正在测试一个企业 HR 系统（Salesforce 平台）中的"新员工入职"流程。
该流程分为全职和兼职两种类型，涉及字段约 30 个，有条件显示逻辑。
当前阶段是回归测试，需要快速覆盖主要场景。
```

---

### 要素 3：具体任务

**作用**：明确你要 AI 做什么，避免"过度发散"或"理解偏差"。

**常见动词**：
- `设计` / `生成` / `列出`（创建类）
- `分析` / `解释` / `找出`（分析类）
- `改写` / `优化` / `翻译`（转换类）
- `评审` / `检查` / `比较`（评估类）

**避免**：一个 Prompt 里包含 3 个以上不同类型的任务。

---

### 要素 4：输出格式要求

**作用**：指定格式让输出可直接使用，减少二次整理。

| 场景 | 推荐格式 |
|------|---------|
| 测试用例 | Markdown 表格 / CSV（指定列名） |
| Bug 分析 | 结构化列表（根因假设 + 验证步骤 + 置信度） |
| 代码 | 带注释的代码块，语言明确 |
| 对比分析 | 表格（两列或多列） |
| 步骤说明 | 有序列表（1. 2. 3.） |

**示例**：
```
输出格式：Markdown 表格，列顺序：用例ID | 场景描述 | 前置条件 | 操作步骤 | 预期结果 | 优先级
```

---

### 要素 5：约束条件

**作用**：设置边界，防止输出偏离需求。

**常用约束类型**：

```
数量约束：至少 10 条用例，不超过 20 条
覆盖约束：必须包含边界值场景和权限验证场景
排除约束：不要包含 UI 样式类测试用例
质量约束：每条用例的预期结果必须可验证，不允许出现"系统正常运行"这类模糊描述
语言约束：全部用中文输出
```

## 第二节：进阶技巧（40 min）

### 技巧 1：Few-shot（少样本示例）

**场景**：你有特定的用例格式或报告风格，需要 AI 对齐。

**方法**：在 Prompt 中给出 1–3 个"期望输出的例子"，然后让 AI 按同样风格生成更多。

**示例**：

```
下面是我们团队的标准 Bug 报告格式示例：
---
【示例 Bug 报告】
标题：兼职员工创建时，工作开始日期允许选择历史日期
严重程度：P1
环境：Chrome 125, Staging 环境
前置条件：已登录 Manager 账号，进入 New Hire 流程
步骤：
  1. 选择员工类型：兼职
  2. 在"工作开始日期"字段选择 2020-01-01
  3. 点击"保存"
预期结果：系统提示"工作开始日期不能早于当前日期"
实际结果：系统保存成功，未报任何错误
---

请按照完全相同的格式，为以下场景写一份 Bug 报告：
[在此描述你的 Bug 场景]
```

---

### 技巧 2：Chain-of-Thought（思维链）

**场景**：复杂的测试分析、根因推断、优先级决策。

**方法**：在 Prompt 中加入"请一步步思考"或"先分析原因，再给出结论"。

**对比示例**：

普通 Prompt：
```
以下日志报错代表什么问题？
[日志内容]
```

思维链 Prompt：
```
以下是一段测试运行时的报错日志。
请按照以下步骤分析：
1. 识别报错的直接原因（错误类型和位置）
2. 推断可能的根本原因（最多3个假设，按可能性排序）
3. 建议验证每个假设的最快方法
4. 给出最终修复建议

日志内容：
[日志内容]
```

---

### 技巧 3：分段式长任务（迭代对话）

**场景**：大模块的用例生成、完整测试计划撰写。

**方法**：把一个大任务拆成多轮对话，每轮输出后基于结果继续追问。

```
轮次 1：先帮我列出这个功能的所有测试维度（不写用例，只列维度）
轮次 2：针对"权限控制"这个维度，展开设计 5 条用例
轮次 3：针对"数据边界"这个维度，展开设计 5 条用例
轮次 4：帮我把上面所有用例合并成一个完整表格，并按优先级排序
```

---

### 技巧 4：迭代优化（追问技巧）

当 AI 的输出不满足要求时，**不要重新发一个全新 Prompt**，而是在同一对话中追问：

| 问题 | 追问方式 |
|------|---------|
| 输出太短/太少 | "请继续补充，至少再增加 5 条覆盖[具体场景]" |
| 格式不对 | "请将上面的输出重新整理成 Markdown 表格，列为：..." |
| 内容不够专业 | "上面第 3 条的预期结果太模糊，请改写为可量化的验证标准" |
| 方向偏了 | "我需要的是[X]，你刚才给的是[Y]，请重新针对[X]回答" |

## 第三节：测试场景专用 Prompt 模板库（20 min）

以下是 5 个可直接使用的测试工作 Prompt 模板，在 M3–M8 各模块中会继续扩充。

### 模板 T-01：功能测试用例生成

```
你是一名有[X]年[系统类型]测试经验的高级测试工程师。
功能描述：[粘贴需求描述]
请设计测试用例，要求：
- 覆盖正常流程、边界值、异常场景、权限控制
- 输出 Markdown 表格，列：用例ID | 场景 | 前置条件 | 步骤 | 预期结果 | 优先级
- 至少 [N] 条，必须包含 [指定的关键场景]
- 预期结果必须具体可验证，禁止出现"系统正常运行"
```

### 模板 T-02：Bug 根因分析

```
你是一名资深 SDET，擅长日志分析和系统调试。
以下是一个测试失败的报错信息：
[粘贴错误日志/截图描述]
请：
1. 识别报错类型和触发位置
2. 列出 3 个可能的根本原因（按可能性从高到低排序）
3. 每个假设给出最快验证方法（1–2 步）
4. 建议最终修复方向
```

### 模板 T-03：等价类 + 边界值分析

```
你是一名测试设计专家，擅长等价类划分和边界值分析。
以下是一个输入字段的约束规则：
[描述字段名称、类型、长度限制、格式要求、业务规则]
请：
1. 划分有效等价类和无效等价类
2. 列出所有边界值（含边界内外各一个）
3. 对每个等价类给出 1 个代表性测试数据
```

### 模板 T-04：需求评审（从测试角度挑刺）

```
你是一名资深测试架构师，以下是一段需求描述：
[粘贴需求文档或用户故事]
请从可测性角度分析：
1. 需求中模糊或矛盾的表述（至少 3 处）
2. 缺失的约束条件或边界定义
3. 可能引发测试盲区的隐性假设
4. 建议补充的验收标准（AC）
输出格式：问题编号 | 原文 | 问题描述 | 建议补充内容
```

### 模板 D-05：测试报告生成

```
你是一名测试管理专家，擅长撰写清晰的测试总结报告。
以下是本次测试的数据：
- 执行用例总数：[N]
- 通过：[N] / 失败：[N] / 阻塞：[N]
- 发现缺陷：[列出主要缺陷]
- 测试范围：[描述]
- 遗留风险：[描述]
请生成一份适合发给项目经理和研发 Lead 的测试总结报告（中文），
格式：概述 → 数据摘要 → 主要问题 → 遗留风险 → 结论与建议
```

## 第四节：常见低效 Prompt 诊断（20 min）

以下是团队中常见的低效 Prompt 模式，逐一分析并给出改进方向：

| 低效模式 | 问题 | 改进方向 |
|---------|------|---------|
| "帮我写测试用例" | 无背景、无格式、无约束 | 添加五要素 |
| "这个功能对吗？" | 没有给 AI 判断依据（无需求、无规则） | 提供需求文档或验收标准 |
| "继续" | 无指向性，AI 不知道继续什么 | 明确说"继续补充[具体维度]" |
| "帮我改一下" | "改"是什么？方向不明 | 说明改什么、改成什么风格/目标 |
| 一次 Prompt 包含5个任务 | 超出单次处理范围，质量下降 | 拆成多轮对话，逐步完成 |

---

## 本模块小结

| 技巧 | 适用场景 |
|------|---------|
| 五要素框架 | 所有场景，建立 Prompt 基本功 |
| Few-shot | 需要 AI 对齐特定格式或风格 |
| Chain-of-Thought | 复杂分析、根因推断 |
| 分段迭代 | 大型用例集生成、完整测试计划 |
| 追问优化 | 任何输出不满意时 |
