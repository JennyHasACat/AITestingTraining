# TOOL-framework-reverse — 框架逆向：代码库透视 + System Prompt 提炼

> 形态 B（纯提示词型）：无脚本，核心资产是 `prompt.md` 的两段式流水线 Prompt。
> 所属模块：M9 第七节「AI 提效小工具 —— 框架逆向：代码库透视 + System Prompt 提炼」。

## 它解决什么问题

接手一个陌生框架时有两个痛点：

1. **读懂慢**：通读整个代码库搞清楚技术栈、目录职责、执行流程，动辄几天；
2. **留不住**：好不容易读懂了，经验只存在脑子里，换个项目又得重来。

本工具用两段式 Prompt 流水线一次解决：

```
代码库 → [Step 1 透视] → 项目理解报告 → [Step 2 蒸馏] → 通用 System Prompt（团队资产）
```

## 两步的关系

| | Step 1：快速了解框架关键信息 | Step 2：逆向提炼通用 System Prompt |
|---|---|---|
| **角色** | 资深 Python 自动化测试平台架构师（只读不改） | 资深 Python 自动化架构师（提炼产出） |
| **输入** | 整个代码库 | 整个代码库（可复用 Step 1 的对话上下文） |
| **产出** | 项目核心信息总结：技术栈 / 目录职责 / 入口与执行流 / 系统类型 / 潜在问题 | 一份可复用的 System Prompt：架构分层 + 工程规范，业务细节抽象为 `[填空变量]` |
| **独立用法** | 新人 onboarding 任意仓库、接手评估 | 把团队已有框架的经验资产化 |

- **固定流水线**：两步按顺序执行，Step 1 的理解报告能让 Step 2 的提炼更准确；
- **Step 1 可独立使用**：只想快速了解一个项目时，跑 Step 1 就够了。

## 用法

1. **脱敏**：喂给 AI 前，去掉密钥、内部域名、真实数据；
2. **Step 1**：把代码库作为上下文（IDE 类 AI 工具直接读全库；对话式工具分批喂：README + 目录树 + 核心脚本），发 `prompt.md` 的 Step 1 Prompt；
3. **Step 2**：在同一会话中继续发 Step 2 Prompt（`[项目名]` 替换为实际项目名）；
4. **人工评审**：AI 提炼的"架构分层"和"工程规范"要对照真实代码抽查 —— AI 可能把"它认为应该的规范"当成"项目实际的规范"；
5. **入库**：评审通过的 System Prompt 按 M9 第二节的标准模板格式贡献到团队 Prompt 库。

## 与 M9 第五节的衔接

Step 2 的产出（通用 System Prompt）正是 M9 第五节「今天就贡献一条」要的素材 —— 从"自己用过的 Prompt"扩展到"从框架里蒸馏出的 Prompt"，让团队 Prompt 库多一条稳定的供给渠道。

## 边界与注意事项

- **上下文窗口**：大仓库一次喂不下。IDE 类 AI 工具（能索引整个工作区）效果最好；对话式工具需分批喂 + 让 AI 先输出目录级理解再逐层深入；
- **先脱敏再喂**：密钥 / 内部地址 / 客户数据必须替换为占位符；
- **产出需评审**：AI 逆向出的规范 ≠ 项目真实规范，入库前对照代码抽查关键条目；
- **只读不改**：Step 1 明确约束"不要修改任何代码"，防止 AI 边读边动你的仓库。
