# TOOL-framework-reverse — 原始 Prompt（溯源用）

> 两段式流水线：Step 1「快速了解框架关键信息」→ Step 2「逆向提炼通用 System Prompt」。
> Step 1 的输出是 Step 2 的上下文基础；两步通常在同一轮对话（或同一会话上下文）中连续执行。

---

## Step 1：快速了解框架关键信息

```
你现在是一个资深的 Python 自动化测试平台架构师。
请仔细阅读整个代码库作为上下文。请你先不要修改任何代码，只做仔细的阅读和审查。
请用中文为我总结这个项目的核心信息：

这个项目使用的核心技术栈是什么？

包括编程语言、主要依赖库、AI/模型调用方式、数据处理方式、外部系统集成方式等。

请梳理并解释目前的目录结构。

说明各个核心目录和脚本的职责，例如配置目录、需求输入目录、测试用例输出目录、自动化工具脚本目录等。

项目的入口文件和核心执行流程是如何组织的？

分析各个主脚本的作用

它们之间的上下游关系

输入、处理、输出分别是什么

这个项目当前属于什么类型的系统？

是脚本工具集、自动化流水线、CLI 工具，还是可运行服务

是否存在统一入口，还是多脚本分工执行

请指出当前工程结构上的主要特点与潜在问题。

例如路径组织、配置管理、模块边界、可维护性、一致性等。
```

## Step 2：逆向提炼通用 System Prompt

```
你现在是一位资深 Python 自动化架构师。
请仔细阅读 [项目名] 的完整代码库，然后做以下事情：

从代码中逆向提炼出它的架构分层标准（每一层的职责）

从代码中逆向提炼出所有工程规范（安全、健壮性、日志、输出格式等）

将以上内容整合成一份【可直接复制给 AI 使用的 System Prompt】

要求：

System Prompt 必须同时包含"架构分层"和"工程规范"两部分

业务细节全部抽象为 [填空变量]，不绑定具体系统

最终附上两个具体场景示例（财务报销系统、招聘系统）

输出格式为 Markdown，可直接保存为 .md 文件使用
```
